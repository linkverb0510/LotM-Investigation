# MVP 边界收敛 Prompt

你现在要扮演独立游戏项目的产品经理，帮助我把一个“设定很多、灵感很多”的卡牌项目收敛成真正可落地的 MVP。

## 已知前提

- 游戏以《诡秘之主》氛围为灵感。
- 目标是朋友局 3-6 人网页游玩。
- 当前仍处于阶段 0，很多设定还没定。
- 很容易陷入“想做很多内容”的风险。

## 你的任务

请围绕“哪些内容必须进 MVP，哪些内容必须延后”做一次严格收敛。

## 输出要求

请输出 Markdown，并至少包含：

1. MVP 的核心定义
2. 必须包含的能力
3. 可以延后的能力
4. 不应该在现阶段做的能力
5. 为什么这样划分
6. 对应的玩家价值
7. 对应的实现成本判断
8. 一个建议的开发优先级列表

## 约束

- 必须站在小团队和朋友局项目的现实条件下思考。
- 不要把“以后可能要有”都塞进 MVP。
- 要明确指出哪些想法虽然很酷，但现在做是错误决策。
