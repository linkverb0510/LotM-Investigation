# 优秀游戏 UI 布局分析

## 文档目的
这份文档不是为了“照抄某个成熟游戏的界面”，而是为了提炼一套适合本项目的布局原则。  
当前项目的问题很明确：房间页信息很多，但主战斗界面没有稳定的信息层级，导致需要纵向滚动、聊天遮挡内容、玩家不容易一眼分辨“现在该做什么”。

因此，这轮分析重点只看三件事：
- 一屏布局如何分层
- 哪些信息必须常驻
- 哪些信息应该折叠、弹窗化或在特定阶段才出现

## 当前项目暴露出的布局问题
结合现有 [room-client.tsx](/C:/Users/李世旺/Desktop/Temp/Secret1/src/components/room-client.tsx) 和截图 [前端界面显示不全.png](/C:/Users/李世旺/Desktop/Temp/Secret1/docs/Screen%20Shots/Test2/前端界面显示不全.png)，当前界面主要有这几个问题：

1. 页面纵向层级太深。
顶部房间信息、错误提示、阶段内容、三列主体、固定聊天框、固定计时条同时存在，导致真正的可操作区被挤压。

2. “公共信息”和“个人操作”没有被明显区分。
玩家列表、日志、手牌、投票都在同一个视觉层级，用户很难快速判断此刻最重要的区域。

3. 固定聊天框覆盖右下角操作区。
聊天本意是辅助沟通，但现在它在视觉和空间上抢占了手牌与操作区域。

4. 界面缺少“阶段驱动”的显式引导。
一个回合制社交推理卡牌游戏，本质上应当让玩家每个阶段只面对少量高价值操作，而不是把所有模块长期展开。

## 参考样本与可借鉴点

### 1. Hearthstone
参考链接：
- [Hearthstone 官方站](https://hearthstone.blizzard.com/)

可观察到的核心布局特征：
- 顶部与底部是对立玩家信息，中间是公共战场。
- 手牌固定在底部，符合“自己手里的资源永远归自己处理”的认知。
- 主要按钮始终靠近操作焦点，不需要跨屏寻找。
- 公共信息集中在战场中央，减少视线跳跃。

对本项目的启发：
- 手牌不应该散落在右侧长列中，更适合底部横向停靠。
- 中央区域应承担“当前阶段的主舞台”，比如日志、事件、投票、抉择弹窗。
- 玩家列表更适合压缩成侧栏或横向头像列，而不是占据一整块高列。

### 2. Marvel Snap
参考链接：
- [Marvel Snap 官方 Game Overview](https://www.marvelsnap.com/gameplay)

可观察到的核心布局特征：
- 每回合的核心决策很短，所以界面把注意力压到“当前能做什么”。
- 公共区域高度集中，边缘信息被尽量压缩。
- 卡牌在不操作时是静态停靠，在需要交互时才进入视觉中心。

对本项目的启发：
- 本项目虽然不是快节奏对战，但也应让“当前回合操作”成为主焦点。
- 不该把日志、手牌、玩家面板全部同时做成大块展开。
- 阶段推进时，最重要的操作区可以放到中央舞台，次要信息缩入边栏。

### 3. Balatro
参考链接：
- [Balatro 官方站](https://www.playbalatro.com/)
- [Balatro Steam 页面](https://store.steampowered.com/app/2379780/Balatro/)

可观察到的核心布局特征：
- 信息密度很高，但通过“区块边界”和“数值层级”保持可读性。
- 关键数值总是固定位置展示，例如筹码、倍率、剩余次数。
- 视觉风格强，但不会牺牲交互清晰度。

对本项目的启发：
- 仪式进度、当前阶段、当前行动者必须固定在顶栏，不应被挤到别处。
- 玩家卡片中的资源条和状态值必须统一格式，否则一旦人数增多会很难扫读。
- 风格化可以做，但不能以牺牲信息结构为代价。

### 4. Among Us
参考链接：
- [Among Us 官方站](https://www.innersloth.com/games/among-us/)

可观察到的核心布局特征：
- 平时只显示必要 HUD，讨论/投票时切换到另一种专用界面。
- 游戏流程是“阶段型”的，所以界面也按阶段切换，而不是把所有功能并列展开。
- 对玩家来说，“当前阶段该做什么”非常明确。

对本项目的启发：
- 讨论与调查不应该共享完全同一套大布局。
- 讨论阶段可以让投票区域上浮，调查阶段则让手牌和日志更突出。
- 如果不想做完全不同的页面，也至少要做“主区域重心切换”。

### 5. Goose Goose Duck
参考链接：
- [Goose Goose Duck Steam 页面](https://store.steampowered.com/app/1568590/Goose_Goose_Duck/)

可观察到的核心布局特征：
- 社交推理游戏的常见做法是把平时操作做轻，把讨论/会议做重。
- 玩家在非会议阶段，不会被过多文本和按钮打断。
- 一旦进入投票阶段，界面会显著转向“人物关系和表态”。

对本项目的启发：
- 玩家列表在讨论阶段的重要性大于调查阶段。
- 投票按钮更适合成为讨论阶段的中心操作，而不是长期停在左栏下方。
- 社交推理的 UI 不只是展示资源，还要服务“观察他人”。

## 适合本项目的一屏布局原则

### 原则 1：顶部只放全局态势
顶部适合放：
- 当前阶段
- 回合数
- 当前行动者
- 仪式进度
- 倒计时

原因：
这些信息属于“所有人都要一直知道的全局状态”，应该成为常驻 HUD。

### 原则 2：中部只保留一个主舞台
中部不应该同时承担：
- 大型日志
- 大型玩家列表
- 大型手牌列
- 大型投票区

更合理的做法是：
- 中央只突出一个“当前阶段最重要”的主舞台
- 其他模块压缩成边栏、抽屉、折叠区或切换标签

### 原则 3：手牌区应固定在底部或底部右侧停靠
原因：
- 手牌属于“个人资源”
- 用户天然会把它理解为“自己持有、随时可操作的对象”
- 底部横向更符合大多数数字卡牌的手势与视线习惯

### 原则 4：聊天必须降级为空间次要元素
聊天是必要功能，但不是主操作区。  
它更适合：
- 右侧可折叠抽屉
- 底部标签页
- 浮层按钮展开

而不适合长期固定覆盖主界面。

### 原则 5：阶段不同，视觉重心必须不同
本项目至少可以分为四类界面重心：
- `lobby`：等待与房间状态
- `briefing`：剧情与身份揭示
- 调查阶段：手牌 + 日志 + 玩家状态
- 讨论阶段：玩家关系 + 投票 + 发言记录

如果所有阶段都共享完全相同的空间结构，用户就会感觉“界面没变化，但规则变了”，这很容易迷失。

## 对本项目的直接设计结论

### 必须保留常驻的信息
- 房间号
- 当前阶段
- 当前回合
- 当前行动者
- 仪式进度
- 自己的灵性和污染

### 可以压缩的信息
- 详细日志
- 聊天记录
- 每位玩家的完整资源细节

### 应当按阶段强化的信息
- 调查阶段：手牌、目标选择、公共日志
- 讨论阶段：玩家列表、投票、聊天
- P0 集结：剧情文本、身份卡、准备状态

## 本项目推荐采用的结构方向
综合参考产品与当前痛点，最适合本项目的方向不是“继续堆三列长页面”，而是：

1. 顶部做成紧凑 HUD。
2. 中央只保留一个主舞台，承担日志/阶段操作/投票等高优先级内容。
3. 玩家信息压缩到左侧或上侧条带。
4. 手牌固定为底部横向托盘。
5. 聊天改成可展开抽屉，不再常驻遮挡。

这会让页面从“文档式堆叠”变成“游戏式界面”。

## 本轮调研结论
优秀卡牌和社交推理游戏在布局上有一个共同点：

它们不会试图让所有信息都同等显眼，而是会通过固定 HUD、主舞台、次级边栏、阶段切换，把玩家注意力引导到“此刻最重要的事情”上。

对本项目来说，这意味着后续重构的核心目标不是“把现有模块塞进一屏”，而是“重新定义哪些模块应该长期常驻，哪些模块应该在合适阶段才上浮”。
