# 硬门槛机制与合作博弈（待实现设计）

> 日期：2026-05-18
> 状态：概念已确认，需细化规则与防卡关逻辑。

---

## 1. 核心逻辑
- **硬性门槛**：特定地点/层级仅允许持有对应“钥匙”（序列/专属行动卡/属性阈值）的角色进行检定解锁。
- **目的**：强制团队协作，凸显序列不对称性。

## 2. 潜在风险与待解问题
### 2.1“钥匙位”消极/拒绝行动
- **场景**：全队需要进入里层，但唯一具备资格的“航海家”因个人任务/恐惧/资源不足拒绝出手。
- **待设计**：是否允许团队消耗公共资源（如全队灵性凑单、强制投票施压）来“推着走”？还是必须接受节奏停滞，通过谈判解决？

### 2.2“钥匙位”被污染/状态异常
- **场景**：关键角色污染度过高，进入深层可能直接失控。
- **待设计**：是否提供“护送”机制？（如通灵者提前净化/代罚者物理护航降低检定难度）

### 2.3 钥匙冲突/竞争
- **场景**：同一层级需要两种不同钥匙（如“破门”+“解密”）。
- **待设计**：是顺序执行（A 开门后 B 进去），还是并行检定（两人同时行动，一人失败另一人连带受挫）？

## 3. 下一步实现建议

- 设计“团队施压/资源分摊”结算逻辑。
