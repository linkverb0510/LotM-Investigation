# 对话思考：终局结算与动态演化

> 日期：2026-05-18  
> 主题：多维结局、个人档案与动态演化

---

## 1. 核心定稿：方向 C + 个人档案

**设计定稿**：摒弃传统的“团队胜利/失败”二元判定，采用基于实际状态的**动态演化结局**。

- **呈现形式**：每局结束时，系统为每位玩家生成一份**截然不同的“个人档案”**（结局独白/余波报告）。
- **判定维度**：
  - **案件完成度**（线索收集率 / 污染控制）
  - **个人状态**（隐情是否暴露 / 污染阈值 / 信任关系）
  - **特殊行为**（是否完成秘密任务 / 是否背叛 / 是否牺牲）

## 2. 体验目标：非零和的复杂余波

- **拒绝绝对胜负**：没有“好人赢/坏人输”，只有“局面变成了什么样”。
- **混合结局示例**：
  - 团队视角：案件成功解决（封印生效）。
  - 梦魇视角：虽然破案，但旧案被揭发，面临停职（个人惨败）。
  - 魔术师视角：团队赢了，但他成功偷走了核心封印物（个人大赢）。
  - 通灵者视角：为了保护队友，污染度爆表，陷入半失控（悲剧英雄）。

## 3. 衍生设计点
- 结算时需展示**全局视角的“案件报告”**与**个人视角的“私密档案”**，让玩家拼凑出完整真相（“原来那天你偷偷拿了那个！”）。
- 动态结局依赖于**状态追踪系统**（State Tracker），需要在代码层记录每个关键节点的分支选择。
