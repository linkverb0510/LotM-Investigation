# 设计参考沉淀约定

## 目的
这份约定的目标，是防止每次做调研都只停留在聊天记录里。  
对一个持续迭代的游戏项目来说，检索和分析本身也是资产。如果不落文档，后面就会重复劳动，甚至同一个问题反复争论。

## 约定内容
每当 agent（Hermes / Codex）检索并分析了某款优秀游戏的 UI 布局、交互设计或游戏机制后，必须将其分析结果写入对应目录下的 Markdown 文档中：

- UI / UX 相关：`docs/ui-references/`
- 游戏机制相关：`docs/game-design-references/`

文件命名格式：
- `{游戏名}-{分析维度}.md`

例如：
- `Hearthstone-战场布局分析.md`
- `AmongUs-阶段驱动界面分析.md`
- `Balatro-高密度信息设计分析.md`

## 最低记录要求
每份参考文档至少应包含：
- 游戏名称与类型
- 设计亮点
- 为什么成立
- 对本项目的可借鉴点
- 风险与不能直接照搬的部分
- 记录日期与参考资料

## 为什么要这样做
一个常见的新手误区是“调研只是为了当前这次任务”。  
更专业的做法是把调研沉淀成可复用的知识库，让下一次设计讨论不是从零开始，而是在已有证据上继续推进。
