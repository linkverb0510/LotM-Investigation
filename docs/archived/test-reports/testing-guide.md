# 游戏全流程测试指南 (Testing Guide)

> **目标**：在当前开发阶段，通过模拟多客户端与调试指令，完整验证游戏核心逻辑。
> **路径**：`docs/testing-guide.md`

---

## 1. 环境准备

1.  **安装依赖**：在项目根目录 (`Secret1/`) 下打开终端：
    ```bash
    npm install
    ```
2.  **启动服务**：
    ```bash
    npm run dev
    ```
3.  **访问入口**：打开浏览器访问 `http://localhost:3000`。

---

## 2. 模拟多玩家环境

为了测试多人互动（投票、攻击），你需要模拟至少 **3 名玩家**：

1.  打开 **3-4 个不同的浏览器标签页**。
2.  **标签页 1**：输入昵称 "Host"，点击"创建房间"。记录房间号 (如 `ABC1`)。
3.  **标签页 2**：输入昵称 "Player2"，输入房间号 `ABC1` 加入。
4.  **标签页 3**：输入昵称 "Player3"，输入房间号 `ABC1` 加入。
5.  **开始游戏**：在 Host 页面点击"Start Game"。

---

## 3. 开发者调试技巧 (重要)

由于 UI 正在开发中，你可能无法仅通过点击按钮完成所有操作。请利用浏览器的 **开发者工具 (F12) -> Console (控制台)** 发送指令。

### 3.1 发送测试指令
在控制台中，你需要找到或模拟一个 Socket 实例。如果 UI 已自动连接 Socket，你可以直接在控制台尝试：

```javascript
// 假设 socket 实例已被挂载到 window，如果没有，请根据 room-client.tsx 找到对应变量
// 以下是伪代码，请根据实际代码情况调整：
const socket = window.socketInstance; 

// 发送 Dev Mode 指令（已在 engine 中实现）
socket.emit('game:dev_cmd', { 
    roomCode: 'ABC1', 
    command: 'set_corruption 50' // 示例：设置当前玩家污染度为 50%
});
```

### 3.2 常用 Dev 指令
*   `set_corruption <0-100>`: 设置污染度 (测试失控判定)。
*   `set_spirit <0-100>`: 设置灵性值 (测试卡牌消耗)。
*   `set_phase showdown`: 跳过流程，直接进入最终对决。
*   `next_round`: 强行结束当前轮次。

## 4. 流程测试清单

### ✅ P0: 集结阶段 (Briefing)
*   **检查点**：
    *   3 个玩家是否都收到了初始手牌？
    *   每个玩家是否分配了角色（老值夜者、极光会渗透者等）？
    *   *注：查看日志区是否显示 "对局开始..."。*

### ✅ P1: 调查阶段 (Investigation)
*   **操作**：
    1.  **常规出牌**：点击打出"灵性感知" (消耗 1 灵性)。
    2.  **观察**：灵性值是否下降？线索数 (`clues`) 是否增加？
    3.  **休息**：尝试点击“休息”（如果有该按钮），灵性应恢复 3 点。
*   **危险调查测试**：
    1.  打出带有 `dangerous_location` 标签的卡牌（如"深渊凝视"）。
    2.  **观察日志**：是否提示 `⚠️ ...在危险区域发现了一个封印物！`？
    3.  **检查手牌**：是否多了一张金色/紫色的卡牌？

### ✅ P2: 讨论与投票 (Discussion)
*   **操作**：
    1.  每个玩家在 UI 中选择一名目标进行投票。
    2.  全部投票完成后，系统自动进入下一阶段。
*   **失控边缘者测试**：
    1.  确认谁是“失控边缘者”。
    2.  大家集中投票给他。
    3.  **观察日志**：是否出现 `✨ 在同伴的感召下...`？
    4.  **状态检查**：如果条件满足，该玩家阵营应变为调查者。

### ✅ P3 & P4: 深入调查与决战前夜
*   **逻辑同 P1/P2**，但此时污染度可能已经累积。
*   **检查封印物副作用**：持有封印物的玩家，每轮结束污染度是否自动 +5？

### ✅ P5: 最终对决 (Showdown)
*   **模拟进入**：在控制台输入 `set_phase showdown`。
*   **检查**：仪式进度条是否显示？玩家是否能使用积累的线索卡进行攻击/防御？

### ✅ P6: 结算 (Finished)
*   **模拟进入**：输入 `set_phase finished`。
*   **检查**：
    *   谁赢了？（是调查者赢还是污染源赢？）
    *   分数计算是否正确？（线索分 + 阵营胜利分）。

## 5. 常见报错处理

*   **报错 "Player already submitted"**：
    *   原因：你在同一轮重复点击了出牌。
    *   解决：等待系统刷新或进入下一轮。
*   **报错 "Not enough spirituality"**：
    *   原因：灵性不足以支付卡牌消耗。
    *   解决：打"休息"卡，或使用 Dev 指令 `set_spirit 20`。
*   **界面不更新**：
    *   原因：Socket 消息未广播。
    *   解决：检查控制台 Network 面板，确认 `game:state` 事件是否触发。
