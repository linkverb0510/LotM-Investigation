# 学习笔记：标签驱动与社交判定机制

> **日期**: 2026-05-14  
> **主题**: 标签系统 (Tags) 与 弱判定逻辑 (Weak Determination) 的实现原理

---

## 1. 标签驱动逻辑 (Tag-Driven Logic)

在引擎中，我们经常需要为卡牌或事件定义特殊属性。
**问题**：如果用 `if (card.id === 'xxx')` 硬编码，会导致引擎与具体卡牌内容强耦合，每次加新卡都要改引擎代码。
**解法**：使用 `tags` 数组。

### 代码实现示例
```typescript
// content.ts
export const ACTION_CARDS = [
  { id: 'abyssal-gaze', tags: ['dangerous_location'] }
];

// engine.ts
if (card.tags?.includes('dangerous_location')) {
  // 触发通用逻辑：掉落封印物
  tryGetArtifact();
}
```
**优点**：
1.  **解耦**：引擎只关心“行为特征”，不关心“具体卡牌”。
2.  **复用**：多个卡牌可以共享同一个 tag，引擎逻辑自动生效。

## 2. 社交博弈：弱判定逻辑 (Weak Determination)

在“失控边缘者”的设计中，我们选择了 **B 方案**：阵营转换受社交行为（投票）影响。

### 设计原理
*   **强判定 (Hard)**：污染度 < 20 自动变阵营。 -> **玩家体验**：像做数学题，缺乏互动。
*   **弱判定 (Weak)**：需要满足“低污染” + “获得救赎标记（投票关注）”。 -> **玩家体验**：
    *   边缘者必须**主动寻求关注**（甚至故意卖破绽）来让别人投票给他。
    *   投票者面临决策：投他是为了**净化**他，还是为了**淘汰**他？

### 实现关键
1.  **状态标记**：`restorationMarks` 记录社交压力/关注度。
2.  **事件触发**：在 `finalizeVoting`（高交互时刻）更新标记。
3.  **状态检查**：在 `resolveRound`（回合结算）检查转换条件。

## 3. 封印物的独立牌库 (Artifact Deck)

之前封印物混在主牌库里，导致抽取概率不可控。
**改进**：
*   **初始化**：`artifactDeck` 独立初始化，不参与 `drawDeck` 的洗牌。
*   **获取途径**：仅通过 `tags` 判定或特定事件获取。
*   **意义**：这不仅是技术上的分离，更是**资源循环**的设计——强力资源必须通过“高风险行为”获取，符合游戏经济平衡。
