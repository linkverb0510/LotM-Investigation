## 任务一：UI 布局重构

### 背景
当前前端页面（`src/components/room-client.tsx`）显示不全，需要向下滑动才能看到所有内容。这不符合卡牌游戏的"一屏可见"体验。

### 执行步骤

#### Step 1: 调研（必做）
检索并分析以下类型游戏的 UI 布局：
- **线上卡牌/桌游**：如 Hearthstone、Marvel Snap、Balatro
- **社交推理类**：如 Among Us、Goose Goose Duck、剧本杀类 App
- **关注点**：
  - 一屏布局策略（顶部 HUD / 中间场域 / 底部手牌）
  - 信息分层（关键信息常驻，次要信息折叠/弹窗）
  - 响应式设计（多分辨率适配）

**输出**：将调研结果写入 `docs/ui-references/优秀游戏UI布局分析.md`

#### Step 2: 草图设计
基于调研，设计 2-3 套布局草图（HTML 原型或文字描述均可），每套草图需包含：
- 页面分区说明（顶部/中部/底部各放什么）
- 关键交互说明（出牌、投票、抉择如何触发）
- 优势与取舍分析

**输出**：将草图写入 `docs/plans/ui-layout-proposals.md`

#### Step 3: 等待用户确认
**停下来！** 向用户展示草图方案，等用户选择或反馈后再继续。不要直接开始编码。

#### Step 4: 重构实现（用户确认后）
基于用户选定的方案：
- 重构 `room-client.tsx` 的布局结构
- 确保一屏内展示完整游戏信息（无纵向滚动）
- 保持现有功能完整（出牌、投票、日志、抉择弹窗等）
- 通过 TypeScript 编译检查

## 任务二：自动化多轮测试脚本

### 背景
当前测试依赖人工打开网页、点击 UI 操作，效率低且无法让 agent 自主验证。需要一个自动化脚本，能在不打开浏览器的情况下跑多轮游戏并记录问题。

### 需求
1. **不依赖浏览器**：通过 Socket.IO 客户端直接与服务端通信
2. **模拟多玩家**：同时创建 3-6 个虚拟玩家连接
3. **自动决策**：每个虚拟玩家在轮到自己时随机/按规则出牌
4. **多轮运行**：自动跑 N 局游戏（N 可配置，默认 10）
5. **问题记录**：自动检测异常状态并输出为 Markdown 报告

### 输出
- 脚本文件：`scripts/auto-test-game.ts`
- 依赖：使用 `socket.io-client`（已安装）
- 报告输出：`docs/test-reports/auto-test-YYYY-MM-DD.md`
- 报告内容需包含：
  - 运行概况（局数、每局轮次、用时）
  - 发现的异常（错误信息、状态异常、逻辑断裂）
  - 通过/失败的统计

### 注意
- 脚本需要能独立运行：`npx tsx scripts/auto-test-game.ts`
- 测试前自动启动 dev server（或要求用户先启动）
- 测试结束后自动清理连接

## 任务三：设计经验记录规范

### 背景
每次检索优秀游戏的设计经验时，都应该沉淀到 docs 目录下，方便后续随时查阅学习，不遗忘。

### 执行步骤

#### Step 1: 创建目录结构
在 `docs/` 下创建或确认以下目录：
```
docs/
├── ui-references/          ← UI/UX 设计参考
│   └── 优秀游戏UI布局分析.md  ← 任务一 Step 1 的输出
├── game-design-references/ ← 游戏机制设计参考
└── test-reports/           ← 自动化测试报告
    └── auto-test-YYYY-MM-DD.md
```

#### Step 2: 建立记录模板
创建 `docs/ui-references/_template.md` 和 `docs/game-design-references/_template.md`，模板包含：
- 游戏名称 + 类型
- 设计亮点（布局/交互/反馈/动效）
- 可借鉴点（对本项目的应用场景）
- 参考资料链接
- 记录日期

#### Step 3: 写入行为准则
在项目根目录或 docs 中写入一条约定文档（如 `docs/design-reference-policy.md`），内容为：
> 每当 agent（Hermes / Codex）检索并分析了某款优秀游戏的 UI 布局、交互设计或游戏机制后，必须将其分析结果写入 `docs/ui-references/` 或 `docs/game-design-references/` 对应的 markdown 文件中。文件命名格式：`{游戏名}-{分析维度}.md`。
