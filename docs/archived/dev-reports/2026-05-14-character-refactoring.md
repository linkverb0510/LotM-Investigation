# 开发报告：角色体系重构与专属卡牌设计

> **日期**: 2026-05-14  
> **任务**: 彻底废除通用牌库，为 6 个 MVP 角色设计基于原著途径的专属能力体系。

---

## 1. 需求与目标

*   **核心问题**: 之前的卡牌系统同质化严重，缺乏“诡秘”风味。
*   **目标**: 
    *   每个角色拥有独特的 **被动技能** 和 **专属牌库 (DECKS)**。
    *   卡牌效果与原著途径能力高度契合（如不眠者的梦境、水手的雷霆）。
    *   明确“出牌目的”（控制、破坏、推进、探查等）。

## 3. 代码重构细节

### 3.1 数据结构升级 (`content.ts`)
*   废除了旧的 `ACTION_CARDS` 数组。
*   引入 `DECKS: Record<string, Card[]>` 映射，每个角色 ID 对应一套专属卡组。
*   卡牌的 `effect` 字段更加细化（如 `purify`, `control`, `halt_ritual`, `trap`）。

### 3.2 引擎兼容 (`engine.ts`)
*   `createInitialGameState` 现在根据分配的 `role.id` 从 `DECKS` 中抽取初始手牌，而非从通用池中抽取。
*   被动技能逻辑将在后续的 `applyCardEffect` 和阶段结算中逐步实现（目前已有基础框架）。

---

## 4. 验证与兼容性

*   **差异化验证**: 
    *   值夜者手牌里不再有“攻击”牌，只有“控制/净化”。
    *   污染源手牌里充斥着“推进仪式”的牌。
*   **兼容性**: 
    *   `Card` 接口中的 `tags` 字段现在用于标记卡牌用途（如 `["healing"]`, `["push"]`）。
    *   UI 层需适配新卡牌的 `effect` 和 `tags` 展示。
