# 开发报告：数据结构与引擎重构 (A & B)

> **日期**: 2026-05-14  
> **任务**: 升级核心数据结构与引擎逻辑，融入 D1-D5 设计文档的神秘学机制。

---

## 1. 需求与目标

*   **目标**: 将策划阶段的“灵性/污染度/仪式进度/封印物/阶段推进”等设定落地为代码逻辑。
*   **约束**: 保持对现有 Socket 服务的兼容，不破坏原有 UI 的显示（保留旧字段）。
*   **核心指标**: 代码能通过编译检查，引擎能正确处理 P0-P6 状态流转与资源结算。

---

## 2. 实施细节

### 2.1 数据结构升级 (`types.ts`)

| 模块 | 变更内容 | 设计依据 |
|------|---------|---------|
| **Phases** | 枚举扩展为 `lobby` → `briefing` → `investigation_up` → `discussion_1`... | D1 单局流程设计文档 |
| **PlayerState** | 新增 `spirituality` (灵性), `corruption` (污染度), `clues` (线索)。 | D4 卡牌消耗体系，D5 资源积累胜利 |
| **Card System** | 新增 `CardType` (action/equip/artifact)，定义 `cost` 接口 (灵性/污染副作用)。 | D4 卡牌分类与封印物设定 |

### 2.2 内容填充 (`content.ts`)

*   **角色库**: 预置 6 个角色（老值夜者、代罚者军官等），绑定了途径 (`Pathway`) 和初始阵营 (`Faction`)。
*   **卡牌库**: 
    *   行动卡：包含“灵性消耗”和“污染副作用”定义。
    *   封印物：加入 `sideEffect` 字段，标记高风险高回报。

### 2.3 引擎核心逻辑 (`engine.ts`)

*   **初始化 (P0)**: 
    *   分发角色与手牌。
    *   **污染预设**: 污染源阵营角色初始隐藏污染度设为 20%，而非 0。
*   **结算循环 (Resolve Round)**:
    *   增加灵性扣减检查：若灵性不足则无法出牌。
    *   增加副作用结算：打出卡牌若带 `corruption_delta`，立即增加玩家污染度。
*   **投票逻辑 (Discussion)**:
    *   **指认正确**: 仪式进度 `-10%`，调查者获得 `线索 +1`。
    *   **指认错误**: 仪式进度 `+5%`，调查者损失灵性。

---

## 3. 验证与兼容性

*   **向后兼容**: 保留了 `PlayerPublicState` 中的 `influence` 和 `suspicion` 字段，确保旧版 `room-store.ts` 和前端组件不会因缺少字段而报错。
*   **状态机**: 引擎现在能根据投票结果自动切换阶段（如 P1 -> P2）。

---

## 4. 后续风险提示

*   **UI 未更新**: 前端组件尚未展示“污染度”和“灵性”条，玩家无法直观看到这些新资源。需尽快跟进 D (UI 适配)。
*   **封印物机制**: 目前封印物仅在抽牌堆中，尚未实现“持有期间每回合自动扣污染”的被动触发逻辑（需引擎支持每回合 Tick 检查）。
