# 本轮开发计划

## 1. 本轮目标

适配升级后的后端游戏状态结构，重构大厅和房间主界面，使前端能够正确展示灵性、污染度、仪式进度、线索等新数据，并提供更清晰的交互反馈。

## 2. 本轮范围

- 重构 `src/components/lobby-client.tsx` 的视觉风格。
- 重构 `src/components/room-client.tsx` 的布局与交互。
- 只在 `src/lib/server/` 的 Socket 分发层内做最小事件参数适配。
- 新增 `docs/codex_ui_report.md` 记录本轮 UI 适配工作。

不做的内容：

- 不修改 `src/lib/game/` 下任何引擎与类型逻辑。
- 不修改 `package.json`，不安装新依赖。
- 不改动游戏规则本身。

## 3. 任务拆分

- 对齐新版 `types.ts` 与现有前端字段使用差异。
- 重构大厅视觉为神秘学/蒸汽朋克风格。
- 重构房间主界面，拆出头部、玩家列表、手牌区、日志区等结构。
- 适配出牌时的目标选择与资源不足提示。
- 产出 UI 适配说明文档。

## 4. 验收标准

- 大厅与房间页面可通过 TypeScript 类型检查。
- 房间主界面能展示 `phase`、`ritualProgress`、`spirituality`、`maxSpirituality`、`corruption`、`clues`。
- 手牌点击时会先校验灵性是否足够。
- 需要目标的卡牌可以选择目标再发送事件。
- `docs/codex_ui_report.md` 完成并说明改动原因。

## 5. 风险与约束

- 后端当前返回的私有数据结构只包含 `roleName`，不包含完整 `role`，因此玩家列表中的头衔展示需要基于已拿到的数据做兼容处理。
- 引擎的目标结算逻辑可能仍较简化，前端只能先做好目标选择参数传递与提示。
- 不能新增依赖，因此弹窗和进度条需用原生 React + CSS 实现。

## 6. 变更记录

- 本轮将聚焦前端 UI 重构与数据适配。
- 游戏引擎、卡牌规则和数据定义保持不变。
