# 流程图集合 — 调查模式

> 本文档汇总调查模式当前使用的流程图（Mermaid），用于可视化单局主流程、回合逻辑、信息流转及系统交互。

---

## 1. 单局游戏主流程图

**用途**：展示从开局到结局的完整 7 个阶段及其流转条件。  
**适用文档**：`单局流程设计文档`、`规则手册`

```mermaid
flowchart TD
    Start((开始游戏)) --> P0
    P0["P0: 案情简报<br/>身份、隐情、初始提示"] -->|全员确认| P1
    P1["P1: 第一轮行动<br/>搜证、接触、压制、净化"] -->|行动轮次达标| P2
    P2["P2: 第一轮讨论<br/>划定重点、生成集体决定"] -->|讨论结算| P3
    P3["P3: 第二轮行动<br/>在压力下继续介入案件"] -->|行动轮次达标或危机升级| P4
    P4["P4: 第二轮讨论<br/>建立信任链与收束执行链"] -->|讨论结算| P5
    P5["P5: 收束阶段<br/>封印、净化、揭露或失败处置"] -->|处置结果确定| P6
    P6["P6: 余波结局<br/>案件真相、组织反应、角色后果"] --> End((结束))

    classDef phase fill:#e1f5fe,stroke:#333,stroke-width:2px;
    class P0,P1,P2,P3,P4,P5,P6 phase;
```

# 2. 单轮行动流程图

**用途**：细化 P1 / P3 阶段中，单个玩家在自己回合内的操作循环。  
**适用文档**：`单局流程设计文档`、`调查模式行动卡分类文档`

```mermaid
flowchart TD
    Start[回合开始] --> Read[阅读当前公共压力与本轮限制]
    Read --> Action{选择主要介入方式}

    Action -->|搜证| Investigate[调查地点 / 尸体 / 档案 / 证物]
    Action -->|接触| Contact[接触人物 / 灵体 / 异常源]
    Action -->|压制| Suppress[封锁 / 护送 / 打断 / 抢占控制权]
    Action -->|掩饰| Conceal[抹除痕迹 / 制造伪证 / 转移注意]
    Action -->|净化| Purify[压低污染 / 稳定局势]
    Action -->|调度| Dispatch[调用组织权限 / 档案 / 支援]
    Action -->|封印物| Artifact[高风险触碰关键物件]

    Investigate --> Check
    Contact --> Check
    Suppress --> Check
    Conceal --> Check
    Purify --> Check
    Dispatch --> Check
    Artifact --> Check

    Check{触发事件或后果?}
    Check -->|是| Event[处理公共事件 / 私密事件 / 行为反应]
    Check -->|否| EndCheck[记录行为痕迹与线索变化]
    Event --> EndCheck
    EndCheck --> Next[轮到下一位玩家或进入讨论阶段]
```

## 3. 玩家视角信息流图

**用途**：展示“系统全知”与“玩家有限视角”之间的信息差异。  
**适用文档**：`调查模式信息架构文档`

```mermaid
flowchart LR
    subgraph System["系统 / 策划视角"]
        S1["案件真相槽位"]
        S2["所有玩家真实隐情"]
        S3["关键物件真实去向"]
        S4["所有 Storylet 触发条件"]
    end

    subgraph Player["玩家视角"]
        P1["自身身份与隐情"]
        P2["公共案件事件"]
        P3["已公开线索"]
        P4["手牌与可用能力"]
    end

    subgraph Reveal["揭示机制"]
        R1["行动结果"]
        R2["讨论结论"]
        R3["异常升级"]
        R4["结局余波"]
    end

    System -.隐藏.-> Player
    System -.驱动.-> Reveal
    Reveal -.逐步解锁.-> Player
```

## 4. 讨论阶段决策流程图

**用途**：说明讨论为什么存在，以及讨论如何改变下一阶段。  
**适用文档**：`单局流程设计文档`、`调查模式产品定义文档`

```mermaid
flowchart TD
    Input["输入：新线索 / 新异常 / 可疑行为 / 私密反应外溢"] --> Debate["案件会议讨论"]
    Debate --> Q1["解释现场：这说明了什么？"]
    Debate --> Q2["划定重点：该盯谁 / 查谁 / 控谁？"]
    Debate --> Q3["资源分配：谁有资格接触关键物件或执行处置？"]

    Q1 --> Decision["产出集体决定"]
    Q2 --> Decision
    Q3 --> Decision

    Decision --> O1["改变下一轮重点地点或重点对象"]
    Decision --> O2["要求某人公开说明 / 陪同行动 / 交出物件"]
    Decision --> O3["建立最终收束执行链"]
```

## 5. 房主 / 玩家 / 系统交互流程图

**用途**：描述实时房间下，各方状态的同步时序。  
**适用文档**：`网络同步策略`、`实现规划`

```mermaid
sequenceDiagram
    participant Player as 玩家客户端
    participant Socket as WebSocket Server
    participant System as 游戏状态机

    Player->>Socket: 提交行动或讨论选择
    Socket->>System: 验证合法性与阶段条件

    alt 验证失败
        System-->>Socket: 返回错误
        Socket-->>Player: 提示错误
    else 验证成功
        System->>System: 更新线索 / 标签 / 事件状态
        System-->>Socket: 广播状态变更
        Socket-->>Player: 更新可见信息
        Socket-->>OtherPlayers: 同步公共信息与各自私有信息
    end

    System->>Socket: 检查是否进入下一轮或下一阶段
    Socket->>Player: 通知切换阶段
```
