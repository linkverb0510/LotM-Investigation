# 开发文档 2026-05-18

## 开发需求
基于「全案真相基准文档」和「角色卡文档」的架构分析结论，为调查模式建立三套基础设施：

1. **黄金路径系统**：阶段锚点 + 调查进度条双层控制，确保每局游戏都有完整叙事弧
2. **占位符文本系统**：支持 `{variable}` 变量替换和 `{if:condition}` 条件文本块
3. **MVP Storylet 池补全**：从 Storylet 全集（43条）中筛选约 19 条新事件，覆盖 P0→P6 全流程

## 开发结果

### 新建文件（3 个）
| 文件 | 说明 | 行数 |
|------|------|------|
| `src/lib/game/investigation-v2/game-state.ts` | 全局游戏状态跟踪器，管理线索发现/污染程度/组织冲突等键值状态，支持 onChange 事件订阅 | ~100 |
| `src/lib/game/investigation-v2/text-resolver.ts` | 占位符文本解析器，先解析 `{if:cond}...{/if}` 条件块，再替换 `{var.path}` 变量，支持角色/地点/计数/状态等多类变量 | ~130 |
| `src/lib/game/investigation-v2/golden-path.ts` | 黄金路径管理器，定义阶段锚点/进度阈值/饱和触发/保底注入，实现 canAdvancePhase/advancePhase/getFallbackAnchors | ~200 |

2. 新建 game-state.ts（状态管理类）→ text-resolver.ts（文本解析函数）→ golden-path.ts（黄金路径管理器）

4. 调整 storylets.ts 中 1 条 phaseHint → 分批新增 19 条 Storylet → 新增 truth-artifacts-pointing
5. 所有文本从 Storylet 全集裁剪至 80-120 字以内

## M3：桥接集成（同日完成）

### 开发需求
将 v2 叙事系统（golden-path + storylets + text-resolver）桥接到现有引擎的 Phase 切换流程中，同时扩展调试命令和前端开发者控制台。

### 开发结果

#### 新建文件（1 个）
| 文件 | 说明 |
|------|------|
| `src/lib/game/investigation-v2/bridge.ts` | InvestigationBridge 类——GamePhase ↔ PhaseHint 双向映射、GoldenPath 生命周期管理、Storylet 按阶段选择与分发、文本占位符解析、调试命令（skipToPhase/injectStorylet/getProgressSummary） |

#### 修改文件（3 个）
| 文件 | 变更 |
|------|------|
| `src/lib/server/room-store.ts` | StoredRoom 新增 investigationBridge 字段；startGame 中初始化桥接器；_hookBridgeOnPhaseChange 在阶段切换时注入公共 Storylet 到游戏日志；confirmReady/applyTurnAction/applyVote/applyStoryChoice 全部挂载钩子；handleDevCommand 新增 skip_to/inject/progress 三条命令 |
| `src/lib/game/investigation-v2/index.ts` | 新增 bridge 模块导出 |
| `src/components/room-client.tsx` | 新增 devCommand/devOpen 状态；sendDevCommand 函数向服务端发送 game:dev_cmd；底部固定 Dev 控制台（输入框+发送按钮）；Ctrl+Shift+D 快捷键切换显示/隐藏 |

#### 集成流程
```
引擎阶段切换（confirmReady/applyVote/applyTurnAction/applyStoryChoice）
  → room-store 记录 oldPhase
  → 执行引擎函数（phase 可能改变）
  → _hookBridgeOnPhaseChange 检测 phase 变化
    → bridge.onPhaseTransition(oldPhase, newPhase, round)
      → 检查保底锚点 → 选择匹配 Storylet
      → 解析公共事件文本 → 写入 gameState.logs
      → 标记线索发现 → 更新调查进度
    → 玩家端收到 game:state 推送 → 日志中显示 📜 Storylet
```

#### 调试命令速查
| 命令 | 示例 | 效果 |
|------|------|------|
| `skip_to` | `skip_to investigation_down` | 跳转到指定 v2 阶段，进度自动对齐 |
| `inject` | `inject seed-public-salt-expansion` | 手动注入指定 Storylet 到游戏日志 |
| `progress` | `progress` | 显示当前调查进度、锚点完成情况 |

#### 已知限制
- 私密 Storylet 目前暂存于桥接器，未按角色分发到前端（待后续实现 per-player private logs）
- engine.ts 的角色 ID 体系（如 `04-aurora-infiltrator`）与 v2 角色 ID（如 `role-01-edwin`）不匹配，桥接使用了独立角色映射
- GoldenPath 的锚点定义为空（需后续从案件配置注入具体锚点事件）
