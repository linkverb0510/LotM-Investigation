# 调查模式信息架构文档

## 1. 文档目标

定义调查模式从玩家视角应该看到什么、不应该看到什么，以及不同阶段的界面重心。

核心原则：

- 玩家看到的是 `案件世界内信息`
- 设计师和开发者才看到 `内部数值与调试信息`
- 同一屏幕只强调“当前该做什么”

## 2. 三层信息模型

### 2.1 公共案件层

所有玩家都能看到，用于建立共同语境。

包括：

- 案件标题与阶段名称
- 当前公共事件
- 已公开线索
- 当前被集体决定重点处理的对象、地点、物件
- 倒计时或紧迫感描述

### 2.2 自我私密层

仅当前玩家可见，用于扮演角色和做决策。

包括：

- 自己的角色身份、组织、头衔
- 本局隐情与个人任务
- 手牌与可用能力
- 私密事件文本
- 自己的风险状态，如接近失控、被盯上、手中关键物件

### 2.3 调试/设计层

默认不出现在正式玩家 UI 中。

包括：

- 精确污染数值
- 行为统计
- 内部标签权重
- 触发阈值
- 状态机阶段码

## 3. 各阶段界面重心

### P0：案情简报

#### 玩家应该看到

- 剧情开场文本
- 自己的角色揭示卡
- 本局隐情摘要
- “准备就绪”按钮

#### 不应出现

- 复杂资源表
- 手牌细节区
- 讨论与投票模块
- 对“后端推进逻辑”的解释

### P1 / P3：行动阶段

#### 玩家应该看到

- 当前公共案情摘要
- 本轮可选动作
- 自己的手牌和行动资源
- 当前重点地点 / 重点对象
- 最近触发的案件反馈

#### 不应出现

- 其他玩家的详细私密状态
- 大量精确内部数值
- 开发术语式阶段编号

#### 界面重心

- 中央：当前要处理的案件对象
- 底部：手牌与动作选择
- 侧栏：玩家状态摘要与公共线索

### P2 / P4：讨论阶段

#### 玩家应该看到

- 本轮讨论问题
- 本轮已知关键线索
- 可选的集体决定项
- 被重点怀疑或被重点授权的目标

#### 不应出现

- 行动阶段所有按钮仍保持可用
- 过多卡牌详情占据主屏
- 只对设计师有意义的统计列表

#### 界面重心

- 中央：讨论议题与候选决策
- 侧边：公共线索与可公开信息
- 辅助区：聊天 / 发言记录

### P5：收束阶段

#### 玩家应该看到

- 当前案件处置选项
- 触发该选项所需的公开条件
- 哪些人物或物件正处于关键位置
- 处置失败的风险提示

#### 不应出现

- 像独立战斗游戏那样的单独面板
- 与前文断裂的新资源系统

### P6：余波结局

#### 玩家应该看到

- 案件真相回顾
- 关键角色命运
- 组织反应
- 污染后果
- 本局关键转折记录

#### 不应出现

- 只有数字结算，没有叙事收尾

## 4. 文案风格约束

### 推荐表达

- “东区雾霾加重，尸体的指尖仍残留着盐粒。”
- “你意识到这份证词和昨夜的祷告记录对不上。”
- “代罚者要求封锁后门，避免任何人单独接近地下室。”

### 不推荐表达

- “P3 已开始，请进行第二轮操作。”
- “后端将在全员确认后切换阶段。”
- “你的 corruption 已达到 57。”

## 5. 玩家视角的必要标签化

某些内部状态需要保留效果，但应该转换成更自然的表现。

| 内部状态 | 玩家视角建议表现 |
|---|---|
| 污染值上升 | “你感到耳边的低语更近了” / “你的呼吸开始紊乱” |
| 被重点怀疑 | “众人的视线开始集中到你身上” |
| 被授权调查 | “你被推上了处理关键证物的位置” |
| 接近失控 | “你的锚正在松动” |

## 6. 当前前端重构时的检查单

- 是否把阶段感写成世界内语言
- 是否删除了只有设计师才关心的暴露信息
- 是否在每个阶段只突出当前最重要的一类操作
- 是否把私密信息和公共信息明确分开
- 是否让讨论阶段真正有“会议感”和“决策感”
