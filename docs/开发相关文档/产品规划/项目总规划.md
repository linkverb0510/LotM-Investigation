# 《诡秘之主》朋友局网页游戏总规划

## 1. 项目目标

做一个面向朋友局的多人在线网页游戏，主题借用《诡秘之主》的世界观气质，但不追求简单贴皮或原著照搬。

当前的产品方向已经收束为：

- **近期主模式**：`调查模式`
- **未来预留模式**：`对决模式`

其中，调查模式是当前唯一进入细化与实现准备阶段的玩法。

## 2. 当前产品定位

### 2.1 调查模式

调查模式是一种 `叙事驱动的超凡案件推理局`：

- 3-6 人朋友房间制
- 单核心案件 + 高变体
- 固定角色 + 可变隐情
- 卡牌承载序列能力、组织权限与非凡介入
- 通过调查、讨论、集体决策与最终处置完成一局

它的目标不是“找出谁是坏人并票死”，而是让玩家在贝克兰德的超凡案件中，真正感受到：

- 组织程序
- 序列代价
- 封印物风险
- 污染蔓延
- 人际信任与隐瞒

### 2.2 对决模式

对决模式保留为未来路线，用于承载更纯粹的卡牌对抗体验，尤其是风暴、战士、猎人等偏战斗型序列。

当前阶段只保留产品占位，不进入细化实现。

## 3. 产品原则

- 先让调查模式成为完整自洽的一局游戏，再考虑第二模式。
- 先把世界观“做进机制里”，再考虑扩写更多文本。
- 先让玩家看懂自己该做什么，再做更复杂的数值和系统暴露。
- 先用固定角色和高变体案件建立重玩价值，再考虑多案件池。
- 先做文档定稿，再进入下一轮代码实现。

## 4. 迭代路线

### 阶段 0：调查模式定义收束

目标是把“调查模式到底是什么”彻底说清楚。

- 定义产品定位、单局流程、讨论作用与收束阶段
- 定义角色如何进入调查模式
- 定义行动卡与 Storylet 体系
- 定义玩家视角信息架构

交付物：

- 调查模式产品定义文档
- 单局流程设计文档
- 调查模式信息架构文档
- 调查模式叙事状态与 Storylet 总表
- 核心案件主文档

### 阶段 1：调查模式 MVP 原型

目标是做出能完整打一局的最小版本。

- 房间创建、加入、准备、开始
- P0-P6 阶段推进
- 行动卡、讨论裁决、案件收束
- 基础日志、断线重连、对局结算

交付物：

- 可运行网页原型
- 核心规则文档
- 基础测试集

### 阶段 2：调查模式深化

目标是让调查模式更有《诡秘之主》辨识度与重玩价值。

- 扩充角色卡与调查模式职责
- 扩充行动卡、私密事件、结局变体
- 增加案件内变体槽位
- 优化节奏、氛围和复盘体验

交付物：

- 角色扩展清单
- 事件池与变体池
- 平衡与节奏说明

### 阶段 3：对决模式规划

目标是基于同一世界观和底层语法，定义未来的 2 人卡牌对决模式。

- 明确共享内核与模式边界
- 明确序列在对决模式中的能力包
- 明确与调查模式的角色复用关系

交付物：

- 对决模式产品定义文档
- 共享规则内核文档

### 阶段 4：上线与稳定性

目标是完成自己的域名部署和长期维护能力。

- 域名、HTTPS、反向代理
- 环境变量与部署配置
- 数据备份、日志、监控
- 错误排查与回滚手册

## 5. 当前建议优先级

1. 先把调查模式文档体系全部定稿。
2. 再进入调查模式代码与交互实现。
3. 调查模式跑通并验证可玩后，再规划对决模式。
4. 最后再做部署与长期稳定性。

## 6. 当前主要风险

- 如果调查模式继续同时背负“未来对决模式”的目标，活文档会持续冲突。
- 如果世界观只停留在设定文案，不落到行动、讨论与收束机制里，玩家仍会觉得像贴皮桌游。
- 如果继续暴露过多内部信息，玩家侧的沉浸感会被严重削弱。
- 如果一开始就铺开多案件池和多模式，会显著拉高文档和实现复杂度。
